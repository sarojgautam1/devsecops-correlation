LLM Verification Experiment — P3 Tier

Testing whether LLM-based code review improves precision in the pipeline's largest, most ambiguous tier.

Why P3?

P3 is the pipeline's largest tier by volume (1,047 findings) and its precision (57.98% under the ML model) leaves the most room for improvement — unlike P1 (already 100%) or P4 (already a strong 16.6% real-vulnerability rate). We tested two prompting strategies on a fixed random sample of 100 P3 findings (91 completed due to free-tier daily rate limits) using Groq's openai/gpt-oss-120b at temperature 0 for reproducibility.

Three-Way Comparison (n = 91)

Rule-based baseline vs. anchored prompt vs. blind (independent) prompt
Honest finding: Neither prompting strategy meaningfully improved precision over the rule-based baseline (56.0%). The blind prompt (57.7%) modestly outperformed the anchored prompt (56.4%), consistent with anchoring bias when the model is told the scanner's claim in advance — but both approaches cost real true positives (6–7 out of 51 genuine vulnerabilities wrongly discarded). We conclude that general-purpose, zero-shot LLM verification does not straightforwardly outperform deterministic rule-based tiering for this task, likely because distinguishing genuine taint-flow vulnerabilities from false positives requires more contextual/data-flow analysis than a single code snippet can provide. This is reported as a rigorously tested negative result, not a discarded experiment.
